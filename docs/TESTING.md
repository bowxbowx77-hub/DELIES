# DELIES — тестирование

Документ фиксирует, **что именно проверено**, чем, с каким результатом и что
проверить было невозможно. Непроверенное не выдаётся за пройденное.

## 1. Как запустить проверки

### Веб-версия (35 автотестов, jsdom)

```bash
npm ci
npm test
```

Тесты запускают настоящее приложение: `main/index.html` загружается в jsdom,
дальше вызывается `boot()` из `main/js/app.js`, и сценарии работают с реальным DOM,
роутером, хранилищем и диалогами (никаких моков UI).

| Файл | Что проверяет | Тестов |
| --- | --- | --- |
| `tests/web/smoke.test.mjs` | загрузка приложения, оболочка, навигация по всем 8 разделам | 2 |
| `tests/web/app.test.mjs` | сценарии пользователя: задачи, календарь, напоминания, заметки, покупки, статистика, настройки, сохранение, импорт/экспорт, темы, языки, ошибки | 18 |
| `tests/web/unit.test.mjs` | даты и повторения, валидация, резервные копии, хранилище, i18n, экранирование текста | 8 |
| `tests/web/security.test.mjs` | отсутствие `eval`, безопасные DOM-вставки, отсутствие сетевых запросов и внешних хостов, отсутствие секретов | 7 |

### Android (15 JVM-тестов)

```bash
cd android
./gradlew testDebugUnitTest
```

| Файл | Что проверяет | Тестов |
| --- | --- | --- |
| `RecurrenceCalculatorTest` | повторения: месячные без «дрейфа» (31 янв → 28 фев → 31 мар), интервалы, `until`, разовые в прошлом, невалидные даты | 6 |
| `RemindersTest` | разбор и валидация payload моста: неизвестные поля, вредоносные id, битые даты, обрезка строк, кодирование повторений | 9 |

### Сборка APK

```bash
cd android && ./gradlew assembleDebug
```
или workflow `.github/workflows/android-build.yml` (кнопка *Run workflow*).

## 4. Что именно не проверено и почему

### 4.1 Установка и запуск на устройстве
В окружении разработки нет Android-эмулятора, нет `adb` и нет физического
устройства; APK собирается в CI. Поэтому установка, первый запуск, реальный показ
уведомлений, восстановление после перезагрузки и поведение кнопки «Назад»
**проверены только на уровне кода и компиляции**, а не на устройстве.

Как проверить вручную (5 минут):

1. Скачать артефакт `DELIES-Android-APK` из Actions, распаковать.
2. `adb install -r app-debug.apk` или открыть файл на телефоне.
3. Создать напоминание на «через 1 минуту», заблокировать экран → должно прийти
   системное уведомление с кнопками «Отложить на 10 минут» / «Готово».
4. Перезагрузить телефон → напоминание на будущее время должно сработать
   (проверка `BootReceiver`).
5. На Android 12/12L: «Настройки → Точные будильники» — без разрешения должно
   появиться предупреждение в разделе «Напоминания».

### 4.2 Инструментальные (instrumented) тесты
`androidTest`-зависимости подключены, но сами тесты не написаны и не запускались:
без эмулятора они не дают результата, а выдавать их за пройденные нельзя.
Юнит-тесты JVM покрывают платформенно-независимую логику (повторения, валидация).

### 4.3 Замечания lint
Lint выполняется в режиме «только отчёт» (не блокирует сборку). Итог последнего
прогона: **19 предупреждений, 0 ошибок**.

Ранее в отчёте было 2 ошибки `NewApi`: `android:windowLightNavigationBar`
(появился в API 27) стоял в темах для базового `minSdk 26`. Атрибут на API 26
игнорируется, но анализатор справедливо указывал на несоответствие. Исправлено
явной аннотацией `tools:targetApi="o_mr1"` с комментарием в `values/themes.xml`
и `values-night/themes.xml`; после этого ошибок нет.

Остальные 19 предупреждений — стилевые и информационные (устаревшие версии
зависимостей в отчёте, отсутствие `@SuppressLint`-подсказок, предложения по
локализации). Отчёт целиком: артефакт `android-lint-report`.

### 4.4 Визуальная проверка интерфейса
Скриншоты в headless-окружении не снимались (нет браузера). Вёрстка проверена
структурно: адаптивные правила в CSS, отсутствие горизонтальной прокрутки
рассчитано через `minmax`/`flex`, но «попиксельная» проверка глазами не выполнялась.

### 4.5 Реальные уведомления в веб-версии
Проверено через подмену Notification API в jsdom: при наступлении времени
создаётся уведомление, пишется история, разовое напоминание отключается.
Поведение реального браузера (разрешения, фоновая вкладка) не проверялось.

## 6. Ограничения автотестов (честно)

- jsdom не является браузером: он не проверяет реальную раскладку, CSS-анимации,
  `backdrop-filter`, работу service worker и системные разрешения.
- Тесты используют localStorage-адаптер (IndexedDB в Node недоступен). Логика
  IndexedDB-адаптера проверяется только на устройстве/в браузере.
- Android: проверено компиляцией, lint и JVM-тестами; поведение системных
  сервисов (AlarmManager/NotificationManager) в живом окружении не наблюдалось.
